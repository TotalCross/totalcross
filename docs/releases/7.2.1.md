# TotalCross 7.2.1

**Release date:** June 25, 2026  
**Commits since 7.2.0:** 21

TotalCross 7.2.1 is primarily a **stabilization and compatibility release** following the major platform modernization introduced in 7.2.0.

The work in this release is predominantly focused on **stabilizing graphics and window handling on production platforms**, particularly the Skia rendering path on Android and iOS, screen rotation and safe-area changes, and image rendering correctness.

It also modernizes Android location services, improves Windows deployment reliability, adds SDL pinch/scale input support, and further consolidates native dependency management around `totalcross-depot-tools`.

Several important regressions exposed by the 7.2.0 modernization were addressed, including distorted images on Android and iOS, stale frames while scrolling on iOS, and incorrect rendering surfaces after layout or safe-area changes.

---

## Migration Summary

No broad API migration or platform compatibility change is required when upgrading from 7.2.0 to 7.2.1.

Applications should nevertheless review the following areas:

1. **Image-heavy applications should upgrade to 7.2.1.**  
   Multiple Skia rendering issues present in 7.2.0 were corrected, including incorrect hardware scaling and unsafe bitmap conversion optimizations.

2. **Retest screens that rotate or depend on safe areas.**  
   Android and iOS now refresh their layout and rendering surfaces more reliably when screen dimensions or safe-area insets change.

3. **Retest scrolling screens containing images on iOS.**  
   A rendering issue that could expose stale framebuffer contents while scrolling was fixed.

4. **Android applications using GPS benefit automatically from the new location implementation.**  
   The deprecated `GoogleApiClient`-based implementation was replaced by `FusedLocationProviderClient`. No application API change is required.

5. **Windows deployments now include the required Visual C++ runtime dependency.**  
   Applications deployed through TotalCross no longer need to rely on the destination machine already having the expected `vcruntime140.dll`.

6. **Windows deployment on case-sensitive filesystems was corrected.**  
   This mainly affects build or deployment environments where filename casing is significant.

There are **no known breaking public API changes introduced specifically by 7.2.1**.

## Highlights

### Developer Action Required

There are **no general source-code changes required** when migrating an application from 7.2.0 to 7.2.1.

Applications affected by graphics, image scaling, screen rotation, safe-area handling, or iOS scrolling regressions in 7.2.0 should prioritize this update and retest those areas.

---

### Major New Capabilities

#### Android GPS migrated to `FusedLocationProviderClient`
**Impact: Medium · Runtime / Compatibility**

The Android location implementation no longer relies on the deprecated `GoogleApiClient` and `LocationServices.FusedLocationApi`.

It now uses **`FusedLocationProviderClient`**, `LocationCallback`, and the modern asynchronous location APIs.

The previous implementation could throw `IllegalStateException` under some conditions and had reports of applications failing to receive coordinates reliably.

The public TotalCross GPS API remains unchanged, so applications benefit from the new implementation without source changes.

**Related:** [`403e4ac`](https://github.com/TotalCross/totalcross/commit/403e4ac44d54277d52fb4b761223f1548ac5dd8f)

---

#### Pinch/scale gesture support on SDL platforms
**Impact: Medium · Feature**

SDL-based desktop targets can now generate TotalCross scale events from multi-touch or trackpad pinch gestures.

The implementation tracks two touch points and maps the gesture to the existing TotalCross multi-touch scale event sequence.

Support was validated on **macOS using a MacBook trackpad**. The implementation is shared by SDL-based targets and is designed to work on other supported SDL environments as well.

**Related:** [`aa9a023`](https://github.com/TotalCross/totalcross/commit/aa9a02366ec57cf58390d766fcba0b002c404ab5)

---

#### Windows deployments now include the Visual C++ runtime
**Impact: Medium · Deployment / Compatibility**

Windows deployment now automatically includes **`vcruntime140.dll`** together with `tcvm.dll`.

The dependency is obtained through `totalcross-depot-tools`, added to the SDK's `dist/libs`, and copied to the generated application during deployment.

This reduces dependence on the target Windows installation already having the compatible Microsoft Visual C++ runtime installed.

**Related:** [`c635329`](https://github.com/TotalCross/totalcross/commit/c635329aa07bf3f2fbba25250e139a5e1ca6806d)

---

### Major Runtime Improvements

#### Skia image scaling restored on Android
**Impact: High · Rendering correctness / Performance**

The Skia rendering path now performs hardware image scaling directly using source and destination rectangles.

This restores the intended optimization introduced in 7.2.0 without requiring `ImageControl` to create an additional scaled image.

The corrected path preserves:

- clipping;
- alpha handling;
- multi-frame image offsets;
- hardware scaling through `hwScaleW` and `hwScaleH`.

The fast `writePixels` path is now restricted to safe 1:1 opaque draws.

**Result**

Applications can again rely on GPU-backed image scaling without the visual corruption that could occur in 7.2.0.

**Related:** [`05b61ed`](https://github.com/TotalCross/totalcross/commit/05b61edc5f55776f8b4b67e0f279c4060af0d452)

---

#### Platform-specific Skia conversion paths tuned for correctness and performance
**Impact: Medium · Performance / Stability**

Some pixel-conversion optimizations originally intended for constrained embedded Linux ARM devices were found to be unsuitable for Android and Apple platforms.

7.2.1 therefore:

- disables the native byte-swap path by default on Android and Apple platforms after testing showed it to be slower on Android;
- disables automatic opaque detection and color-type conversion optimizations on Android and Apple where they could cause rendering errors;
- simplifies the common pixel-conversion path.

The optimizations remain configurable and available for platforms where they provide a benefit.

**Related:** [`8c29626`](https://github.com/TotalCross/totalcross/commit/8c2962684c94160d274267cf9828b1592e340473) · [`04df583`](https://github.com/TotalCross/totalcross/commit/04df5836f9bade663ba6ea5c3cbf6b2916b39044) · [`9ddbc16`](https://github.com/TotalCross/totalcross/commit/9ddbc169dffc78717f0dd65758eb8d0ba76383d9)

## Changes for SDK Users

### Android

#### More reliable GPS implementation

Android GPS now uses `FusedLocationProviderClient` instead of the deprecated `GoogleApiClient` integration.

Location updates are registered through `LocationCallback`, while the last known position is retrieved asynchronously through `getLastLocation()`.

No change is required to applications using the TotalCross GPS APIs.

**Related:** [`403e4ac`](https://github.com/TotalCross/totalcross/commit/403e4ac44d54277d52fb4b761223f1548ac5dd8f)

---

#### Safe-area changes now trigger layout refresh

When Android reports a change in safe-area insets, TotalCross now checks whether the effective inset values actually changed and, when necessary, generates a screen-change event.

This ensures that application layouts are recalculated after changes to system bars, orientation, or other conditions affecting the usable display area.

**Related:** [`6ba786f`](https://github.com/TotalCross/totalcross/commit/6ba786fb711878fa34ef5e26c2c827360d7e8f35)

---

#### Image rendering corrections

The Android Skia path received several related corrections:

- hardware scaling now works without generating an additional scaled image;
- unsafe bitmap color-conversion optimizations are disabled;
- clipping and alpha are preserved during scaled draws;
- multi-frame images preserve the correct source offsets.

These changes address image distortion and scaling regressions introduced by the graphics changes in 7.2.0.

**Related:** [`05b61ed`](https://github.com/TotalCross/totalcross/commit/05b61edc5f55776f8b4b67e0f279c4060af0d452) · [`04df583`](https://github.com/TotalCross/totalcross/commit/04df5836f9bade663ba6ea5c3cbf6b2916b39044)

---

### iOS

#### Stale frames during scrolling fixed
**Impact: High · Bug fix**

The iOS Skia rendering path could reuse stale framebuffer contents during scrolling, temporarily displaying old image contents outside their expected position or container.

The rendering lifecycle was corrected by:

- preserving the EAGL backing store;
- removing the unnecessary clear after presentation;
- submitting pending Skia GPU work before presenting the renderbuffer;
- keeping canvas state balanced while the screen is shifted;
- preserving invalidations that arrive during presentation.

This significantly improves rendering stability on image-heavy scrolling interfaces.

**Related:** [`c4663b0`](https://github.com/TotalCross/totalcross/commit/c4663b075adb0ff90b81ee7e5494e20cd69a7408)

---

#### Rendering surface now follows actual layout size
**Impact: High · Bug fix**

The iOS rendering drawable is now resized when the underlying view dimensions change instead of relying only on orientation changes.

The framebuffer dimensions are obtained from the actual renderbuffer after it is recreated, and the OpenGL viewport is updated accordingly.

Safe-area changes are also propagated independently of orientation changes.

This fixes cases where rotation or layout changes left the TotalCross rendering surface using obsolete dimensions.

**Related:** [`114a770`](https://github.com/TotalCross/totalcross/commit/114a770cf1ac760ae87468ccb53b59f2ce968a0c)

---

### SDL Desktop

#### Scale events from trackpad and multi-touch input

SDL finger events can now generate TotalCross `MULTITOUCHEVENT_SCALE` events.

On macOS, SDL's trackpad touch mode is explicitly enabled so MacBook trackpad pinch gestures can participate in the same event path.

**Related:** [`aa9a023`](https://github.com/TotalCross/totalcross/commit/aa9a02366ec57cf58390d766fcba0b002c404ab5)

---

### Windows Deployment

#### Visual C++ runtime included automatically

`vcruntime140.dll` is now obtained through the native dependency infrastructure, packaged under `dist/libs`, and copied to Win32 deployments.

**Related:** [`c635329`](https://github.com/TotalCross/totalcross/commit/c635329aa07bf3f2fbba25250e139a5e1ca6806d)

#### Case-sensitive deployment environments fixed

Windows deployment no longer assumes case-insensitive host filesystem behavior.

This fixes deployments generated from environments where filename case must match exactly.

**Related:** [`286cfd7`](https://github.com/TotalCross/totalcross/commit/286cfd7a324902a8bb0b63b0e99df9b3636295c9)

## Relevant Bug Fixes

### Android image scaling and distortion
**Impact: High**

A group of Skia changes introduced during the 7.2.0 graphics modernization exposed invalid assumptions in image conversion and scaling.

7.2.1 corrects the issue by:

- using Skia's normal scaled-draw path when dimensions differ;
- limiting direct pixel writes to safe cases;
- disabling color conversion and opaque-computation optimizations known to corrupt scaled rendering on Android and Apple targets.

**Related:** [`04df583`](https://github.com/TotalCross/totalcross/commit/04df5836f9bade663ba6ea5c3cbf6b2916b39044) · [`05b61ed`](https://github.com/TotalCross/totalcross/commit/05b61edc5f55776f8b4b67e0f279c4060af0d452)

---

### iOS scrolling artifacts
**Impact: High**

Fixed stale Skia frames appearing during scrolling by correcting framebuffer preservation, GPU submission, canvas state, and invalidation handling.

**Related:** [`c4663b0`](https://github.com/TotalCross/totalcross/commit/c4663b075adb0ff90b81ee7e5494e20cd69a7408)

---

### Android safe-area changes not refreshing the UI
**Impact: Medium**

Changes in Android safe-area insets now trigger the same layout refresh mechanism used for screen changes.

This prevents the application from continuing to use stale client-area dimensions after system UI changes.

**Related:** [`6ba786f`](https://github.com/TotalCross/totalcross/commit/6ba786fb711878fa34ef5e26c2c827360d7e8f35)

---

### iOS drawable size after rotation and layout changes
**Impact: High**

The actual OpenGL drawable is now recreated when its view dimensions change, and the new framebuffer size is propagated to the VM.

This fixes incorrectly sized or displaced application rendering after rotation or other view-layout changes.

**Related:** [`114a770`](https://github.com/TotalCross/totalcross/commit/114a770cf1ac760ae87468ccb53b59f2ce968a0c)

---

### Skia bitmap memory deallocation
**Impact: Medium · Stability**

Converted Skia bitmap buffers allocated as arrays are now released with `delete[]` instead of the scalar delete operation.

This removes a mismatched allocation/deallocation pair and avoids undefined behavior in bitmap processing.

**Related:** [`ad12f5d`](https://github.com/TotalCross/totalcross/commit/ad12f5d94fac46300f73e4cb4e2853203b88c4e3)

---

### iOS Skia builds referencing obsolete OpenGL texture functions
**Impact: Medium · Build / Stability**

Legacy OpenGL font-texture reset code is now excluded from the iOS Skia path.

The Skia implementation no longer provides the GL texture helpers used by the legacy renderer, so allowing that code to compile could result in references to unavailable functions.

**Related:** [`77d3645`](https://github.com/TotalCross/totalcross/commit/77d3645cd249a96a547a02b377f062e6337f9e38)

---

### Android GPS reliability
**Impact: Medium**

The replacement of the deprecated Google location API also fixes a runtime reliability problem: the previous implementation could throw `IllegalStateException` and had reports of failing to deliver coordinates.

**Related:** [`403e4ac`](https://github.com/TotalCross/totalcross/commit/403e4ac44d54277d52fb4b761223f1548ac5dd8f)

---

### Windows deployment on case-sensitive hosts
**Impact: Medium**

Corrected filename handling in the Windows deploy process so deployment also works when executed from a case-sensitive filesystem.

**Related:** [`286cfd7`](https://github.com/TotalCross/totalcross/commit/286cfd7a324902a8bb0b63b0e99df9b3636295c9)

## Internal Project Changes

### Skia is now linked statically on Android
**User impact: Indirect · Build architecture**

Android no longer packages Skia as a separate `libskia.so`.

Instead, the depot-provided **`libskia.a` static library** is linked into the TotalCross VM through the `Skia::Skia` CMake target.

The integration was also updated for newer Skia APIs, including the transition from `GrContext` to `GrDirectContext`.

This reduces special-case library packaging and makes Android consume Skia through the same centralized native dependency infrastructure used by the other platforms.

This is an **integration and linkage change, not a Skia source-version upgrade**.

**Related:** [`cf7dba0`](https://github.com/TotalCross/totalcross/commit/cf7dba059a4595fbd58c5ccbcc1dc2b53f83c1d6)

---

### Native dependency versions are now owned by `totalcross-depot-tools`
**User impact: Indirect · Build architecture**

7.2.0 introduced `totalcross-depot-tools` as the centralized native dependency infrastructure.

7.2.1 completes an important part of that transition: the TotalCross repository no longer maintains its own hard-coded fallback release tags for native dependencies.

Instead:

- compatible default versions come from the depot's `deps.yml` manifest;
- explicit environment overrides remain supported;
- dependency repositories and release tags are only passed when overridden;
- CI caches are keyed from the dependency manifest, automatically invalidating when the depot dependency set changes.

This establishes the depot manifest as the authoritative description of the native dependency bundle rather than duplicating version information across Gradle, CMake, and CI.

**Related:** [`20dac9c`](https://github.com/TotalCross/totalcross/commit/20dac9c7e20e6001c1b22d2cc3a852ea37340621) · [`bb7a375`](https://github.com/TotalCross/totalcross/commit/bb7a375cafd7906f435fcd03b2c592ae6e282183) · [`ee59c2e`](https://github.com/TotalCross/totalcross/commit/ee59c2e403637239a9d6a62866114806790ee40e)

### Native Dependency Version Audit

Unlike 7.2.0, **7.2.1 does not introduce an upstream version upgrade for the existing core native dependency set**.

| Dependency | 7.2.0 | 7.2.1 | Change |
| --- | --- | --- | --- |
| SQLite | 3.32.3 | 3.32.3 | No upstream version change |
| mbedTLS | 3.5.2 | 3.5.2 | Artifact rebuilt as `3.5.2-r2` |
| zlib | 1.3.1 | 1.3.1 | Artifact rebuilt as `1.3.1-r2` |
| zlib-ng | 2.1.6 | 2.1.6 | Artifact rebuilt as `2.1.6-r2` |
| libpng | 1.6.48 | 1.6.48 | Artifact rebuilt as `1.6.48-r2` |
| Skia | `158dc9d7` | `158dc9d7` | Same source revision; depot artifact `r1 → r3` |
| Visual C++ Runtime | — | 14 (`vcruntime140.dll`) | New Windows deployment dependency |

The `-r2` and `-r3` suffixes are **depot artifact revisions**, representing rebuilt or repackaged artifacts and expanded platform/build support. They do not represent newer upstream library versions.

Therefore, 7.2.1 should not be documented as upgrading SQLite, mbedTLS, zlib, zlib-ng, libpng, or the Skia source revision.

---

#### New Visual C++ runtime dependency

The depot gains an explicit **VC Runtime 14** dependency, and TotalCross 7.2.1 directly consumes it for Windows deployment.

The SDK build retrieves the dependency from the depot and packages `vcruntime140.dll` under `dist/libs`, while the Windows deployer copies it beside `tcvm.dll` in generated applications.

This is a **new runtime dependency/distribution change**, rather than an upgrade of an existing TotalCross dependency.

**Related:** [`c635329`](https://github.com/TotalCross/totalcross/commit/c635329aa07bf3f2fbba25250e139a5e1ca6806d)

---

#### Depot additions not consumed as new TotalCross 7.2.1 dependencies

During the same development period, `totalcross-depot-tools` also gained packaging support for:

- libjpeg 10;
- libjpeg-turbo 3.1.4.1.

These are **not classified as TotalCross 7.2.1 dependency upgrades**, because the 7.2.1 TotalCross build does not introduce them as new direct runtime dependencies.

In particular, JPEG codec support remained disabled in the relevant depot-built Skia configurations during this release cycle.

### Native dependency artifact coverage expanded
**User impact: Indirect**

The native dependency depot received broader platform-specific prebuilt support during the 7.2.1 development cycle, particularly across:

- Windows architectures;
- macOS;
- iOS device;
- iOS simulator;
- Android.

This work produced new release revisions of several otherwise unchanged upstream dependencies, explaining the `-r2` and `-r3` artifact revisions listed above.

It improves build reproducibility and reduces the need to obtain compatible native libraries from the host system.

The iOS CI build now explicitly configures CMake for the iOS target so Xcode and the native dependency discovery logic resolve the correct platform artifacts.
