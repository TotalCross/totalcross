# TotalCross 7.2.0

**Release date:** June 8, 2026
**Commits since 7.1.0:** 378

TotalCross 7.2.0 consolidates several years of platform evolution into a major modernization release.

The work in this release is predominantly focused on **modernizing and stabilizing the production platform**: updating the Android, iOS, and macOS runtimes; modernizing camera and TLS support; improving networking, rendering, memory usage, and runtime performance; updating deployment requirements; and substantially modernizing the build and CI infrastructure.

The release also removes obsolete technologies and platforms, including Litebase and Windows Phone 8 support, while introducing capabilities such as safe-area handling, CameraX-based capture, native file picking on iOS, improved HTTPS handling, and more efficient image processing.

At the project level, 7.2.0 also introduces **`totalcross-depot-tools` as the centralized infrastructure for native dependencies**, moving the acquisition and platform-specific packaging of libraries such as Skia, zlib-ng, libpng, SQLite, and mbedTLS out of the main repository's individual dependency implementations.

---

## Migration Summary

Before upgrading an application from 7.1.x to 7.2.0, review the following items:

1. **Android 6.0 / API 23 is now the minimum supported Android version.**
   Applications targeting older Android versions can no longer use the 7.2.0 Android runtime.

2. **Litebase has been removed.**
   Applications still using Litebase must migrate their persistence layer, preferably to SQLite or another supported solution.

3. **`JSONTokener.skipTo()` has been removed.**
   Code relying on this method must be rewritten to work without backward navigation of the JSON input source.

4. **Review application layouts for safe-area support.**
   Applications that assume the entire physical screen is available for interactive content should use `Window.getSafeAreaInsets()` where appropriate.

5. **Replace `UIColors.shiftScreenColor`.**
   The field is deprecated. Use `UIColors.unsafeAreaColor` instead.

6. **Review Android permissions.**
   Storage, media, Bluetooth, external-storage management, and package-installation behavior changed to comply with newer Android versions.

7. **Windows Phone 8 is no longer supported.**

8. **Review applications depending on removed or temporarily disabled integrations.**
   Scandit support on iOS was removed, while Firebase on iOS and Ads on Android were temporarily disabled in this release.

9. **Manual HTTPS socket-factory configuration is normally no longer necessary.**
   `HttpStream` now selects the appropriate socket factory automatically.

#### `JSONTokener.skipTo()` removed

**Impact: High for affected applications · API change**

`JSONTokener` can now parse directly from an `InputStream`, allowing JSON sources to be processed without first loading the complete contents into memory.

As a consequence, `JSONTokener.skipTo()` was removed because it depended on lookahead and backward movement that cannot be guaranteed for sequential streams.

**For developers**

Code using `skipTo()` must be rewritten so it does not depend on repositioning the input source.

**Related:** [`[0d86d55](https://github.com/TotalCross/totalcross/commit/0d86d557c149f2a04c718b459bb2f8f9f0bd8226)`](https://github.com/TotalCross/totalcross/commit/0d86d557c149f2a04c718b459bb2f8f9f0bd8226)

### Major New Capabilities

#### Safe areas become part of the window model

**Impact: High · Feature**

The SDK now understands regions of the display that are not safe for interactive application content, such as notches, system bars, and other screen cutouts.

The release introduces **`Window.getSafeAreaInsets()`**, with native platform support and integration into window client-area calculations.

The simulator also gained safe-area simulation through:

* `/safeAreaPortrait top,left,bottom,right`
* `/safeAreaLandscape top,left,bottom,right`
* updated device presets.

Android also provides native safe-area inset information.

**For developers**

Applications using custom layouts or drawing directly against the physical edges of the display should be retested. Use `Window.getSafeAreaInsets()` instead of assuming that the entire screen can safely contain interactive content.

#### Modernized TLS implementation with multiple provider support

**Impact: High · Feature / Security / Compatibility**

Secure socket handling was modernized around **mbedTLS**, replacing axTLS as the primary implementation.

mbedTLS entered the 7.2.0 development cycle at **3.2.1** and was upgraded to **3.5.2** before release.

The SSL subsystem was subsequently reorganized to support **multiple providers**, allowing different TLS implementations to be selected depending on platform and requirements. The axTLS-based provider remains available where still required.

New abstractions include `SSLContext`, `SSLContextSpi`, and `SSLSocketFactory`.

**Benefit**

This removes the architectural dependency on a single TLS implementation and provides a more maintainable foundation for future security updates.

### Major Runtime Improvements

#### Reduced image-processing cost and memory pressure

**Impact: High · Performance / Memory**

The image pipeline received several optimizations.

When hardware acceleration is available, `ImageLoader` can leave final scaling to the GPU rather than generating another resized image in software. This reduces CPU work, intermediate allocations, copies, and the risk of memory fragmentation.

For JPEG images, `ImageLoader.jpegMemorySaving` was introduced with a default value of `0.8`, allowing a smaller raster to be decoded when the GPU will perform the final scaling.

Additional improvements include:

* `mmap` usage in `getJpegBestFit` on POSIX platforms;
* smaller `createJpg` output;
* earlier release of discarded GPU textures;
* public access to `Image.freeTexture()`.

**Related:** [`[4d01b9e](https://github.com/TotalCross/totalcross/commit/4d01b9e4506dcb52c5b49c11730332dec1834371)`](https://github.com/TotalCross/totalcross/commit/4d01b9e4506dcb52c5b49c11730332dec1834371) · [`[9bbf62c](https://github.com/TotalCross/totalcross/commit/9bbf62ccf0143e07a0773e23627e7a351abe1a44)`](https://github.com/TotalCross/totalcross/commit/9bbf62ccf0143e07a0773e23627e7a351abe1a44) · [`[e09a624](https://github.com/TotalCross/totalcross/commit/e09a624e34b2fe7a4156e74e293914d9f0bf9fc2)`](https://github.com/TotalCross/totalcross/commit/e09a624e34b2fe7a4156e74e293914d9f0bf9fc2)

This modernization provides the build foundation required for current Android APIs, CameraX, newer Google Play Services, and current Play Store requirements.

### Native dependency management moved to `totalcross-depot-tools`

**User impact: Indirect · Build architecture**

TotalCross 7.2.0 introduces **`totalcross-depot-tools`** as the centralized mechanism for acquiring and consuming native third-party dependencies.

Previously, native libraries used a mixture of bundled source trees and dependency-specific download/build logic inside the main TotalCross repository.

The new infrastructure introduces a shared dependency checkout under:

```text
TotalCrossVM/deps/totalcross-depot-tools
```

and updates CMake, Gradle, and CI to obtain platform-specific artifacts and CMake integration from that repository.

The initial integration covers:

* Skia;
* zlib-ng;
* libpng;
* SQLite;
* mbedTLS.

This centralizes native dependency management, reduces bundled third-party source code in the main repository, and makes local and CI builds use the same dependency acquisition model.

7.2.0 introduces this architecture, but the `totalcross-depot-tools` checkout was **not yet pinned to an immutable repository revision**. Explicit checkout pinning was introduced in later development.

**Related:** [`[2970716](https://github.com/TotalCross/totalcross/commit/2970716391760a1a994096b2e488386656ac6ea9)`](https://github.com/TotalCross/totalcross/commit/2970716391760a1a994096b2e488386656ac6ea9)

### Native dependency modernization

The move to centralized dependency management was accompanied by several actual library upgrades.

#### zlib → zlib-ng 2.1.6

The bundled classic **zlib 1.2.8** used by the modern native build path was replaced by **zlib-ng**.

zlib-ng was upgraded during the development cycle and the final 7.2.0 dependency is **zlib-ng 2.1.6**.

Classic zlib remains in compatibility paths where required, including WinCE and Linux aarch64.

This change both modernizes the compression implementation and allows the bundled zlib source tree to be removed from the normal build path.

#### libpng 1.6.23 → 1.6.48

The bundled **libpng 1.6.23** was replaced by a modern external dependency.

The library was initially upgraded to 1.6.40 and subsequently to **1.6.48**, which is the final version used by 7.2.0.

The old bundled libpng source tree was removed from the normal dependency model.

#### TLS backend modernized to mbedTLS 3.5.2

The previous TLS architecture was based primarily on **axTLS 2.1.5**.

7.2.0 introduces mbedTLS at version 3.2.1, later upgrades it to **mbedTLS 3.5.2**, and reorganizes SSL support around multiple providers.

mbedTLS becomes the primary implementation on supported modern targets, while axTLS remains available as an alternate implementation where required.

#### SQLite dependency consolidated on 3.32.3

SQLite went through multiple version experiments during 7.2.0 development.

An upgrade to **3.36.0.3** was tested but subsequently reverted after a query was found to run approximately 20 times slower with that version.

The final 7.2.0 native dependency therefore uses **SQLite 3.32.3**.

On the JavaSE/SDK side, `sqlite-jdbc` was upgraded from:

* **3.8.7 → 3.32.3.3**

The changelog intentionally reports the final released state rather than the intermediate 3.36.0.3 version.

#### Skia moved to centralized dependency management

Skia acquisition and build integration were moved into `totalcross-depot-tools` together with the other native dependencies.

This is primarily a **dependency-management change rather than a Skia version upgrade** in 7.2.0.

The distinction is important: Skia's source and artifact handling changed substantially, but no separate Skia version bump needs to be attributed to this release.

### Android runtime dependency modernization

The Android runtime also received significant library updates.

Notable tag-to-tag changes include:

* Google Play Services Maps: **11.6.2 → 18.2.0**
* Google Play Services Location: **11.6.2 → 21.1.0**
* Firebase Core: **11.6.2 → 15.0.2**
* Firebase Messaging: **11.6.2 → 15.0.2**
* ZXing Android Embedded: **2.3.0 → 4.3.0**
* ZXing Core: **3.2.0 → 3.3.0**
* CameraX: newly introduced, ending the release at **1.5.2**
* AndroidX Core: **1.17.0**
* AndroidX LocalBroadcastManager: **1.1.0**
* Guava Android: **31.0.1-android**
* desugar JDK libraries: **2.1.5**

Obsolete ZXing integration dependencies were removed as part of the scanner modernization.

The Firebase dependency upgrade should not be interpreted as full Firebase availability on every platform: **Firebase support on iOS remained temporarily disabled in this release**, and Android Ads were also temporarily disabled because of dependency compatibility constraints.

### iOS dependency modernization

The iOS build configuration was also updated:

* minimum CocoaPods deployment target: **iOS 10.0 → 12.1**
* Firebase Messaging: **4.3.0 → 10.8.0**
* obsolete Firebase Instance ID dependency removed;
* explicit Firebase Core pod removed from the final Podfile;
* YouTube player helper remains on the existing 1.0.x dependency line.

Although the Firebase Messaging dependency itself was modernized, the TotalCross Firebase integration on iOS was **temporarily disabled** during 7.2.0 because of crashes and API compatibility changes.

### SDK and converter dependency modernization

Several Java-side build and tooling dependencies were updated as well.

Notable changes include:

* SQLite JDBC: **3.8.7 → 3.32.3.3**
* Thumbnailator: **0.4.8 → 0.4.20**
* ASM: **7.0 → 9.7.1**

The ASM upgrade is particularly relevant to the bytecode conversion toolchain because it provides support for newer Java class-file formats.

### Deployment tooling modernization

The deploy toolchain was also updated and made less dependent on binaries permanently stored inside the repository.

#### Protocol Buffers compiler

`protoc` was upgraded from **3.20.1 to 21.0**.

Instead of requiring the compiler binary to remain bundled with the project, the appropriate host version can now be downloaded on first deploy.

The download logic includes support for ARM64 macOS hosts.

#### Bundletool

Android `bundletool` is now obtained on demand instead of being permanently bundled with the SDK source tree.

These changes reduce the size and maintenance burden of the repository while allowing deployment tools to be versioned independently.

**Related:** [`[05fa2e5](https://github.com/TotalCross/totalcross/commit/05fa2e5)`](https://github.com/TotalCross/totalcross/commit/05fa2e5)

### Simplified SDK distribution

Runtime dependencies are now packaged under `dist/libs` and resolved by artifact name rather than through hard-coded version-specific paths.

This makes the assembled SDK less dependent on the repository's original dependency layout and prepares distribution for the external dependency model introduced with `totalcross-depot-tools`.

### CI and release engineering

The GitHub Actions infrastructure received substantial modernization:

* new and refactored build workflows;
* updated Linux build jobs and images;
* native ARM64 runner support;
* package and release pipeline improvements;
* iOS simulator builds adapted to ARM64 hosts;
* expanded cross-platform build validation;
* dependency caches adapted to externally managed native artifacts.

The project also introduced:

* clearer commit conventions;
* a commit-message template;
* changelog-generation scripts;
* updated contribution guidelines.

---

### Legacy project cleanup

In addition to user-visible removals:

* obsolete projects and build files were deleted;
* old integrations were removed;
* duplicate filesystem and NinePatch code was consolidated;
* architecture-specific macros were moved out of `tcvm.h`;
* bundled third-party dependency source trees were reduced as libraries moved to the external dependency infrastructure;
* libpng integration was updated to use public APIs instead of internal headers.

---

## R&D and Experimental Work

No major R&D initiative in the 7.2.0 release needs to be presented separately as experimental technology.

The work in this release is predominantly focused on **modernizing and stabilizing the production platform**: updating the Android, iOS, and macOS runtimes; camera, TLS, networking, rendering, performance, native dependencies, and build infrastructure.
